# Qubriant Technologies website

A responsive, multi-page website in HTML, CSS and JavaScript with Qubriant branding, original vector artwork, a video homepage and accessible animations.

## Run and edit

Run `npm.cmd run dev` from this directory or its parent workspace. Open http://127.0.0.1:4173. No dependency installation is needed.

- `build.mjs`: shared templates and generated pages.
- `data.mjs`: services, industries, portfolio projects and articles.
- `generate-artwork.mjs`: editable source for retained Qubriant SVG artwork and product mockups.
- `social-icons.mjs`: header icons; profile links can be supplied later.
- `dist/styles.css` and `dist/app.js`: styling, motion and browser interactions.
- `dist/assets/qubriant/`: Qubriant logo and existing team/partner portraits.
- `dist/assets/qubriant-home-background.mp4`: the supplied homepage video.

Run `npm.cmd run build` after template, data or artwork changes. Then run `npm.cmd run check` and `npm.cmd test`. `browser_check.py` checks responsive layouts and interactions in local Chrome.

## Behavior and hosting

Menus, quote dialogs, industry switching, portfolio filters, article search, theme preferences and reduced-motion support are included. The homepage video is muted and loops, without an on-screen playback button. The local server supports MP4 byte ranges.

Enquiry forms prepare an email draft for review and sending in the visitor's email application. No message delivery backend is configured.

For static pages, deploy `dist/`. The AI chatbot additionally needs the Node backend described below. Existing hosting identity and Git history are preserved. The workspace root is a launcher for this single website.

The homepage and services directory use the six colorful industry photographs in their service cards. Card copy and pictures occupy separate areas for readability; images are lazy-loaded and respect reduced-motion settings.

Technology cards and the contact layout follow the requested Softgen reference. The original contact workflow background was restored. The Google reviews panel links to the user-supplied Qubriant Business profile (https://share.google/oACFFEw17A396cywm). No live review API/feed is configured, so the page does not display unverified ratings or copied customer reviews. Actual review retrieval requires a separately configured provider or Google API integration.


## Qubriant AI assistant

The floating Ask Qubriant button is included on all pages. Browser code calls POST /api/chat; only the Node backend contacts OpenRouter. The selected model is openai/gpt-6-luna. API credentials are read from environment variables or the ignored local .env file, never from dist/. Use .env.example as a template for other environments.

Run npm.cmd run dev for the full site and chatbot. For production, deploy server.mjs, chat.mjs, data.mjs and dist/ on a Node 24 host; configure OPENROUTER_API_KEY, OPENROUTER_MODEL, PORT, HOST and SITE_ORIGIN using hosting secrets. Set HOST=0.0.0.0 if the host requires it; SITE_ORIGIN must match the public HTTPS origin. Existing static hosting alone cannot run the chatbot endpoint. Never upload .env in a public/static bundle.

GET /api/health returns the server status and whether chat credentials are configured, without exposing them. It does not verify the provider key; a real chat request is required to confirm the provider accepts it. The site stores the theme preference in browser storage and remembers essential-only cookie consent in a first-party cookie for six months. Visitors can reopen the notice using Cookie settings. No analytics or advertising cookies are enabled.

The assistant uses the site's service, project and FAQ data; it does not submit enquiries or book meetings. Chat history stays in page memory and clears on reload or New chat. Messages are forwarded to OpenRouter and its model provider; see the updated privacy page. Basic process-local controls allow ten requests per IP per ten minutes, one hundred total per hour and three concurrent requests. Provider calls time out after 45 seconds. Multi-instance production hosting should add a shared rate limiter and provider spending limits.

Checks: npm.cmd test runs mocked provider validation/error/rate-limit and server tests; npm.cmd run check validates generated-page references and JavaScript syntax. `python browser_check.py --chat` and `node check-chat-live.mjs` each make one real provider request and consume API credits; they are optional and should only be run when an external provider request is approved.
